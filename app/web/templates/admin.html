How to get a token

  1. Open accounts.google.com/EmbeddedSetup with your browser's developer console on the Network tab.
  2. Sign in with the account you want ATLAS to download as. Accept the Google terms if prompted — there may be a pause afterwards.
  3. Select the last request to accounts.google.com, open its Cookies tab, and find the response cookie named oauth_token.
  4. Copy its value — it begins oauth2_4/ — and paste it below.

⚠️ That value works once. ATLAS exchanges it for a long-lived token, stores that encrypted, and never shows it again. If the exchange fails you will need a fresh one — the old is spent either way.

{{ csrf_field(csrf_token) }}

Starts with oauth2_4/.

{# ⚠️ Grouped by architecture, because that is the part of this choice that goes quietly wrong: a 32-bit profile makes Play hand back an armeabi-v7a build, which is a perfectly valid APK that is simply the wrong binary for an arm64 tablet. #}

Decides which build Play serves. The default is a Pixel 9a — arm64, which suits this fleet.

Agent updates

Publishing a build tells every enrolled device to replace its own agent with it, at its next check-in. Devices that are failing to apply policy are skipped until they recover, and a device is left alone until it has checked in cleanly once on the build it is already running.

There is no rollback. Android refuses to install an older versionCode over a newer one, so a build that will not start cannot be recalled from here — the only cure is another build with a higher code, delivered by hand to every device that took the bad one. Publish builds you have already run on a test instance.

Provisioning bypass code

This is a master bypass code used to skip the permissions step during provisioning. Enter it on the device when setup is blocked because a required permission has not been granted.

{{ bypass_pin }}

Generated once for this server and fixed thereafter — every install has a different one. It is checked by this server, so the device needs to reach it; the code is never sent to a device or embedded in an enrollment QR.

⚠️ What it does not do: it grants no access to this server and no control over an enrolled device. It only lets whoever already holds a valid enrollment token finish provisioning a tablet without granting the required permissions — producing a device that reports as DEGRADED and is offered no agent updates until they are granted.
